# 骨格の大きな飛び: 原因と再生上の対処

グループ2録画001、SDK ID 0 の 7.894、7.927、7.961秒の元BODY CSVでは、同一IDの骨盤がそれぞれカメラ座標 [0.89,-0.74,5.30]、[0.53,0.62,3.17]、[0.93,-0.80,5.59] m。画像上の骨盤yも375.2→726.7→371.1 pxと往復し、同時刻のSDK全体信頼度は98.4、98.1、98.5。画像間の全時刻の人物正解はないが、この急変は座標変換や再生描画より前のSDK出力に既に存在する。グループ3録画001にも同様に、ID 2が2.140→2.173秒に12.54m変化する例がある。どちらも現在のSDK設定における事例であり、原因が検出・ID交代・遮蔽・深度・SDKの平滑化等のどれかは確定していない。

再生ギャラリーの以前の3D表示は、その時刻の関節の極端な座標で表示倍率も変化していた。現在は表示範囲を録画全体の位置から求め、時刻ごとの関節では変えない。3D高さ範囲は−1〜3m、X/Yは位置の0.5〜99.5パーセンタイルを使うため極端な点は表示外になる場合がある。SDK座標の数値自体は変えていない。

表示のみの試験的な保留: 同じSDK IDの3連続観測で、中間点の前後移動がそれぞれ0.75m超かつ6m/s超、前後端の位置差が0.5m＋4m/s×経過時間未満の場合、中間点を保留する（各隣接時間は0.15秒以下）。0.75m超かつ6m/s超の線分も表示しない。人間の正解による性能検証をしておらず、誤って除外する可能性や異常を残す可能性がある。前後を補間せず、原データ・CSV・解析結果を変更しない。画面上の「急激な飛びを保留」を外せば元の観測に戻る。既存の人物をまたぐ混合骨格については、この条件を満たさない例もあり解決していない。
