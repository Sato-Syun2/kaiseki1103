2. P0で比較の基準を先に作る。

ACCURATE_GEN2を主比較対象とする。既存の骨格数比較を「ID精度が最良」という根拠にはしない。まず録画001・002・003・025・044・048を候補として、画像と条件表を確認する。単独歩行、左右の追い越し、遮蔽、遠方、ID分断を含むように選び直してよい。

調整用と評価専用の録画を分離し、分割・評価区間・対象者をチューニング前に固定する。候補の初期分割は調整用001・003・025、評価用002・044・048。条件が偏る場合は、結果を見て選別する前に変更理由を記録する。評価専用データで調整した場合、その結果を独立評価と呼ばない。

元画像を目視して、人物の対応、解析領域にいる時間、可視／部分遮蔽／完全遮蔽、追い越しイベントを注釈する。明瞭な画像根拠と曖昧な区間を分ける。SDK IDや改善後の軌跡を正解にしない。被験者番号が読めなければ録画内の人物A・Bに留め、条件表から番号を推測しない。録画番号と試行番号の対応も確認する。

再生画像の時間分解能を超えるイベント精度を主張しない。3Dの前後差だけで決めた追い越し時刻は派生推定とし、画像注釈との違いを記録する。

| 指標 | 定義・集計方法 |
|---|---|
| ID取り違え | 確認済み人物の解析用IDが別人物へ移るイベント数。総数と録画別件数 |
| 誤統合 | 別人物の観測を同じ軌跡へ結合したイベント数 |
| 軌跡分断 | 可視の同一人物が複数の解析用IDへ分かれた件数 |
| 観測に基づく位置取得率 | 固定した評価区間のうち、対象者の有効な現在時刻の観測に裏付けられた位置を得た時間割合。補間・運動予測を除外 |
| 最大欠測 | 同じ評価区間で、観測に基づく位置が連続して得られない最長時間 |
| 追い越し前の取得時間 | 固定した追い越し前区間で取得できた時間と、追い越し何秒前から確認できたか。単一の早期誤検出も併記して除外 |
| 曖昧な対応の割合 | ID未確定時間と保留区間数。保留を増やすだけでID精度改善としない |
| 距離・高さ誤差 | 独立した既知点に対する符号付き偏り、MAE、RMSE、95パーセンタイル、欠測率。未測量なら未評価 |

旧データの比較は同じ時刻・同じ対象区間で行う。30fps出力との比較では共通時刻での比較と元レートでの比較を分け、点数の増加を精度改善とみなさない。全48録画についてはラベル不要の健全性指標も出すが、全録画の真のID精度を確認したとは表現しない。

3. P1で追跡用の入出力を整える。

原観測を不変として、品質判定、人物対応、位置推定、表示を分離する。旧CSV・JSONを読める互換アダプターを設け、新形式には `schema_version` を付ける。位置が作れない2D観測も保持する。SDKが出す骨格は推定であり、信頼度を位置誤差の確率として解釈しない。

| 情報 | 最低限保持する項目 |
|---|---|
| 原観測 | recording、画像時刻ns、フレーム番号、SDK ID、追跡状態、2D/3D関節、信頼度、元ファイル参照 |
| 人物対応 | 録画内で安定したtrack_id、確認できた場合のみsubject_id、元SDK ID、対応の根拠、採用／保留／拒否理由 |
| 推定位置 | 廊下X/Y/Z、位置に用いた身体部位、位置の不確かさまたは未推定の明示 |
| 推定の出所 | SDK由来推定、現在の部分観測に基づく推定、補間、運動予測、2Dのみ、欠測。位置の出所とIDの確実さは別項目 |
| 再現情報 | 入力・校正・設定のハッシュ、処理版、SDK版、実行コマンド、処理成功／失敗／未検証 |

モデル間・録画間でSDK IDを共有しない。被験者の手動対応は別ファイルとして保持し、変更履歴を追えるようにする。元のbody_idを修正値で上書きしない。

4. P2で人物IDの維持を実装する。

実時間差を使った移動予測と候補観測の対応付けを実装する。位置・速度の連続性、2D位置、可視な身体部位、衣服の特徴を組み合わせる。まず小さく検証可能な構成として、カルマンフィルタと一対一割当、分断区間の前後照合を候補にする。単純な近傍割当との差を評価し、必要性のない複雑化を避ける。

SDK IDは対応の手掛かりの一つとし、同じIDでも急な位置変化・外観変化があれば区間を分割して再確認する。追い越しでは前後・左右の順序が変わるので、その順序を人物の固定条件にしない。生データ中の重複検出を識別し、同一フレームの別人物を一つのtrack_idに入れない。

姿勢や見え方で衣服特徴が変わるため、重なった領域や背景を外観特徴に混ぜない。現在の画像から使える簡易特徴を基準にし、追加学習や外部ReIDモデルは必要性が検証されてから検討する。全身が見える区間から対象者の特徴を登録し、遮蔽後は同じ人物かを複数の手掛かりで確認する。

失踪直後に新しい人物と決めつけず、一定時間は対応候補を保持する。この保持時間と、位置を運動予測で出力する時間上限は別設定とする。未検出の間ずっと位置を出し続けない。位置ゲートは距離に応じた誤差を考慮し、未校正の廊下座標だけで実在する観測を強く除外しない。

誤対応の疑いがある区間には理由を記録し、手動アンカーによる修正を適用できるようにする。自動結果とアンカー適用後の結果を分けて評価する。

5. P3で骨盤が見えない場合を扱う。

有効な骨盤を基本とし、両腰、胸・肩、頭の観測を補助にする。代替部位を骨盤と同じ座標だとみなさず、遮蔽前後の身体部位間の位置差や姿勢を使う。推定誤差が大きい場合は2Dの人物対応だけ継続し、3D位置を欠測にする。頭の画素を床面への射影変換に直接入れて歩行位置としない。

可視性判定、2Dの画面内判定、信頼度、部位間の幾何を確認する。SDKの `OK` だけでは当該フレームの直接検出と予測を完全に区別できない可能性があるため、SDK由来推定の出所を保守的に記録する。前景人物の深度が後方人物に付く問題にも注意し、深度マスク等がない旧出力では根拠以上の回復を主張しない。

代表画像に写っていた手前の別人物を、上半身の補完によって実験参加者へ取り込まないよう、対象領域と開始時の人物対応を併用する。2人試行でも検出数を機械的に2人へ切り詰めない。

補間は、同一人物である前後の根拠があり、動きが整合する短い区間だけに適用する。初期比較値として0.2秒・0.5秒を試してよいが、採用値は評価で決める。完全遮蔽や長い欠測は、欠測または不確かさ付き予測として残す。後方人物が一度も観測されていない開始区間へ、一定速度の軌跡を延長して実測扱いしない。

平滑化は追い越し開始・横移動を消さないようにする。生観測、対応付け後、補間／平滑化後を別出力し、画像注釈に対するイベント時刻のずれも評価する。

6. P4で既存の再生・一括処理に統合する。

`build_group001_replay.py` には原観測と改善後の軌跡を渡し、`group001_replay_template.html` には元SDK ID、解析用ID、確認済み被験者番号を区別して表示する。観測に基づく位置、補間、予測、未確定を線種・凡例・詳細で分ける。最終観測点を長時間表示する場合は経過時間を明示し、現在位置と誤認させない。

旧約0.1秒画像と30fps人物データは別タイムラインとして同期する。画像と骨格の時刻差を表示し、画像のない時刻を撮影済みフレームのように扱わない。描画のための最近傍画像選択を、解析用時刻の丸めに流用しない。

`process_zed_model_comparison.py` と `process_group001_batch.py` に解析設定・出力版を伝える。入力データのタグと解析結果の版を分離し、同じ入力で再処理できるようにする。既存HTMLがあるという理由だけで別設定の実行をスキップしない。入力・設定・処理版が一致する場合だけ再利用する。

出力は `results/tracking_v2/<run_id>/` など未使用ディレクトリに置く。既存のCSV、HTML、校正候補、SVOを上書きしない。人物画像・注釈・軌跡が意図せずGit管理されないよう、新しい出力先も `.gitignore` へ反映する。集計レポートと個人単位のデータの扱いは既存方針に合わせる。

7. P5でSDK側の再書き出しを準備する。

共有SDKコードの内容とハッシュを記録し、プロジェクト内に追跡可能な改修版を置く。共有先へ渡す場合は `zed_sdk_package/tracking_v2/` など新しい場所に配布し、稼働中の旧版を上書きしない。正本、配布物、転送手順をREADMEで明確にする。

| 修正 | 要件 |
|---|---|
| 保存頻度 | 骨格・検出は全取得フレーム、画像は独立した保存間隔。SDKへの入力を間引かない |
| 時刻・新規性 | image timestamp、可能なら検出timestampとis_newを保存。重複・古い結果・欠落を識別。ns値の精度を保持 |
| 追加項目 | SDKが提供する範囲でposition、velocity、2D box、マスク参照、共分散等を保存。非対応は欠損理由を記録 |
| 設定 | 人物検出閾値、minimum_keypoints_threshold、prediction_timeout_s、skeleton_smoothingを明示的に記録・設定可能にする |
| 頭部検出 | PERSON_HEAD_BOX_ACCURATEの出力を選択可能にする。骨格とのSDK ID一致を仮定せず、別パス出力でも時刻・画像位置で対応付ける |
| 安定性 | SDK失敗と正常EOFを区別し、途中終了を完了扱いしない。完了マニフェストに予定／取得／保存フレーム数とエラーを書く |
| 画像の共有 | ファイル名だけで再利用しない。元SVO、フレーム、時刻、解像度が一致することを確認 |
| 長時間処理 | CSV等を逐次出力し、全フレーム分の大きな配列を無制限にメモリへ保持しない |

BODYモデルの基準はACCURATE_GEN2/BODY_34、深度の基準はNEURALを維持する。BODY_38へ変えて改善したと仮定しない。頭部検出や深度モードの効果は別の比較として測る。[SDKの骨格追跡パラメータ](https://docs.stereolabs.com/docs/development/zed-sdk/modules/body-tracking/using-the-api)、[頭部検出の公式説明](https://docs.stereolabs.com/docs/development/zed-sdk/release-notes/5-x/5-5)

SDKがUbuntu側にない場合でも、共通のシリアライズ、設定検証、出力検証、PowerShell実行手順は完成させる。モック試験・構文確認をSDK実機検証と呼ばない。Windows側の短いSVO試験、必要なコマンド、返却ファイル一覧を引き継ぐ。頭部検出をダミー出力で完成扱いしない。

8. P5〜P6で校正処理と撮影検証を行う。

既知点の入力形式、座標変換の推定、独立点での誤差レポートを先に実装する。床・壁からの既存推定は候補として残す。初めに剛体変換で座標系を合わせ、その後で残差の距離依存性を調べる。根拠のない高次補正や、既存の人物骨格を正解にした床合わせは行わない。

| 校正録画 | 記録する内容 |
|---|---|
| 長手方向 | 3・5・7・9・11・13・15mなど、実際の解析範囲をカバーする既知位置。届かない遠方は精度未検証として残す |
| 左右方向 | 中央と左右の歩行位置。床上のX/Yを測量して記録 |
| 高さ | 根元と床上1m・1.5mなど。十分な幅と模様のあるつや消し標的を使い、測量点と画像上の点を対応付ける |
| 繰り返し | 各位置で数秒静止、複数回測定。校正用と評価用を別にする |
| 独立検証 | 4・6・8mなど補正に使っていない位置・別の繰り返し録画で確認 |
| 人物 | 被験者が既知位置に静止する録画と単独歩行。標的測距と人体位置推定を別々に評価 |

座標原点はカメラ光学中心の床面投影位置、長手方向距離は廊下軸に沿った距離とする。斜距離や標的表面までの距離との違い、標的厚さを記録する。中央一直線だけの点配置では3D姿勢の制約が不足するので、左右と高さの違う点を含める。校正と評価で使用する画像・深度条件を揃える。

新規校正がない間は、単位・変換・合成点での回復を検証し、実距離精度は未検証として出力する。旧録画に新しい設置の校正を無条件に適用しない。配置・解像度・内部パラメータ・校正IDを関連付ける。

撮影比較は、まず同じ配置で720p/30fpsと1080p/30fpsを比較し、次に側方位置・高さなどの配置を比較する。解像度と配置を一度に変えて効果を混同しない。照明・露出・開始位置・歩行条件を揃え、各条件を繰り返す。ZED 2iでは解像度で画角が変わるため、足元や左右端の欠けも評価する。[公式の解像度・画角資料](https://support.stereolabs.com/articles/8809264540-what-is-the-camera-focal-length-and-field-of-view)

後方人物を完全遮蔽中にも観測するには、別方向からのカメラ等が必要になる。初期実装で完全遮蔽を解決済みとしない。追加センサー融合は、外部姿勢・時刻同期・対象者対応の校正を別作業として定義する。LiDARにも遮蔽があるため、追加すれば必ず回復するとはみなさない。

9. 検証と採用条件を分けて記録する。

必要な試験は、人物の接近・追い越し・交差、SDK IDの変更と再利用、短い欠測・完全遮蔽、前景深度の混入、途中で画面外へ出る第三者、2Dのみの観測、身体部位の切替、不規則な時刻、旧新形式の読込み、座標変換を対象とする。実装をなぞるだけの試験や、追跡結果自身を正解にした試験は避ける。

| 区分 | 判定条件 |
|---|---|
| 実装完了 | P0〜P5が実装され、意味のある試験が通り、既存48録画の比較結果・失敗理由が出力される。SDK実機と新校正が未検証なら、その範囲を明記した実行可能な引継ぎがある |
| 自動対応の採用 | 固定した確認済み評価区間で、旧処理に対して新しい人物取り違え・誤統合を増やさず、取り違えまたは分断を減らす。保留時間や取得率の悪化を隠さない |
| 部分観測の採用 | 少なくとも確認可能な後方人物の区間で、補間を除く観測に基づく取得時間が増える。追加点を元画像へ戻して対象者と整合することを確認 |
| 平滑化・補間の採用 | 出所が全点で追跡でき、誤対応を橋渡しせず、イベント時刻・横移動を不当に変えない |
| 新校正の採用 | 校正に使わない既知点で距離帯・左右・高さ別の誤差と欠測率を比較し、改善と悪化の両方を報告する |
| 1080p・頭部検出の採用 | 共通条件で取得率・ID誤り・欠測・視野欠けを比較。処理時間・保存量も測り、効果のない変更を既定値にしない |

採用条件を満たさない候補は既定値へ反映せず、比較可能な候補として残す。「実装完了」「現データで改善確認」「新撮影で検証済み」を別々に報告する。絶対位置の正解がない旧データについて「10cm以内」等の達成を主張しない。

同じ原因の失敗を設定変更だけで無制限に繰り返さず、失敗の根拠を分類して次の仮説を選ぶ。未解決の必要作業がある場合はGoalを完了にせず、外部依存で進めなくなった場合は環境のGoal状態管理ルールに従って、必要なデータと再開手順を報告する。

10. 最終成果物を揃える。

変更コード、設定、互換形式の説明、意味のある試験、基準比較の再実行コマンド、48録画の集計、代表例の同期再生、ID対応の監査情報、SDK配布版とPowerShell手順、校正入力テンプレート、撮影手順を残す。品質の採否は `results/tracking_v2/<run_id>/report.md` 等へ集約し、検証済み・未検証・不採用・要確認を明記する。

モデル設定とGoalの使い方は[公式モデル資料](https://learn.chatgpt.com/docs/models)と[公式Goal資料](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)を参照した。トークン予算はユーザーが指定していないため、この計画では固定しない。
