# グループ2・3：深度の廊下座標再生

> **2026-11-05更新：以下の旧Windows出力手順は使用しない。** ユーザーの指定により、深度・画像はWindowsローカルに保存し、共有するのは解析後の人物座標のみとする。新しい手順は [Windowsローカル解析・座標のみ共有](depth_local_coordinates_20261105.md) を参照する。

## 現状

[グループ3録画018の上面再生](../results/tracking_v2/group003_018_corridor_depth_replay_20261105_03/index.html)は全297フレームを画像と同期して再生する。廊下に沿うXと横方向Yはメートル単位・同縮尺。カメラの床面投影が原点、深度から推定した壁を実線、LiDAR幅を使って推定した反対側の壁を破線で表示する。グループごとに校正と原点は異なる。校正はいずれも暫定で、別の測量基準による絶対位置精度は未評価。

点は人物マスク内で選んだ深度の可視表面代表点で、身体中心や足の位置ではない。IDも暫定であり、欠測・対応未確定を補間しない。実記録には隣接フレームでも0.1秒を超える時刻の空きがあるため、上面図はこの空きも線で結ばない。黄色などのマスク色はフレーム内の検出順、枠と上面図の色は暫定IDを表す。

グループ2の55録画とグループ3の54録画のBODY出力と対応する校正を検証し、元SVOのWindowsパス、フレーム数、SVO・BODY・校正のハッシュを共有先の `depth_group002_003_inventory_20261105_01.csv` に記録した。深度が全フレームそろっているのは録画018のみ。残り108録画、36,230フレームにはWindows SDKによる深度書き出しが必要。

録画018の実績（約400 MiB/90フレーム）から単純に見積もると残りは共有先だけで約157 GiB。内容により変動する。Windowsローカルにも同程度の一次出力が残り、Ubuntu解析結果にも別途容量が必要。共有先の空きは準備時点で約27 GiBのため、一括で全件を共有しない。外部保存先の確保または保存方針の決定まで、数録画ずつ進める。出力は自動削除しない。

## 初回：Windows SDK PCで各グループ1録画を出力

SDK 5.5.1で動いたPython環境のPowerShellで実行する。元SVOは読み取り専用。グループ2録画001は375フレーム、グループ3録画001は361フレームで、それぞれ69フレーム以下に分ける。各区間はSVOハッシュ検証後にWindowsローカルへ出力・検証し、成功後に共有する。共有先の空きはこのスクリプトでは確認しない。両PCの空き容量に余裕が必要で、失敗時はローカル出力とログを残す。

```powershell
$Package = '\\tsclient\_data_experiment_data\kaiseki1103\zed_sdk_package\tracking_v2_20261105_depthgroups_01'
$Exchange = '\\tsclient\_data_experiment_data\kaiseki1103\exchange'
$Inventory = Join-Path $Exchange 'depth_group002_003_inventory_20261105_01.csv'

foreach ($Group in @('2', '3')) {
  powershell -NoProfile -ExecutionPolicy Bypass -File "$Package\export_depth_inventory.ps1" `
    -Inventory "$Inventory" -Group "$Group" -Recording 'recording_001' -ExchangeRoot "$Exchange"
  if ($LASTEXITCODE -ne 0) { throw "グループ $Group の出力で停止しました。ローカル出力とログを残してください。" }
}
```

出力名とローカル出力の上書きは拒否する。既存区間がある場合に再実行するには原因を確認し、`-RunId` で新しい名前を指定する。各録画は全SVOを区間ごとに読み直すため、撮影時間より長い処理となる。SDK書き出しスクリプトは従来成功した処理を使うが、今回追加した一覧駆動のPowerShell自体はWindows実機未検証。

## Ubuntuで個別録画を処理

全区間を受領後、各クリップのSVO・時刻・画像・校正を検証する。各区間を録画018と同じ画像マスク・深度選択で解析し、全フレームを結合してからIDを一続きに付け直す。次の例は各録画を別ディレクトリへ保存する。失敗時は途中のディレクトリを保全し、原因を確認して新しい `--output-root` でやり直す。

```bash
INV=/data/experiment_data/kaiseki1103/exchange/depth_group002_003_inventory_20261105_01.csv
EXCHANGE=/data/experiment_data/kaiseki1103/exchange
for GROUP in 2 3; do
  python3 -m corridor_tracking.depth_batch_process \
    --inventory "$INV" --group "$GROUP" --recording recording_001 \
    --exchange-root "$EXCHANGE" \
    --output-root results/tracking_v2/depth_group002_003_20261105_01 \
    --depth-python .venv-depth/bin/python --model models/yolov8n-seg.pt || break
done
```

再生は各結果の `replay/index.html`。異なる録画はWindows側の `-Recording` とUbuntu側の `--recording` を同じ番号に変える。グループ3録画018は既存結果を使うため一覧駆動の重複出力を拒否する。各区間は別SDKパスであり、同一SVO・時刻・カメラ設定を確認できても、1パスで全フレームを書き出した場合と深度の内部状態が同一とは限らない。
