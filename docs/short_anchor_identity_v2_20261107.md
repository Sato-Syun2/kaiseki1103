# 短い基点を使ったID候補

10 m版の旧候補選択では、対象IDと参照IDの両方に位置付き観測が10以上必要だった。一方、その後の既存の時系列処理は対象IDの位置５観測と有効速度３サンプルから動作する。グループ２録画005では対象ID 8が７観測しかなく、候補を作れていなかった。

新しい `corridor_tracking.short_anchor_identity_v2` は対象IDを５観測以上、参照IDを従来どおり10観測以上で探し、既存の時系列処理の時間差、速度、高さ、距離、競合の条件を適用する。条件を満たす対象と参照の組が複数あれば保留し、条件に合わない候補を無理に割り当てない。座標・時刻は変えず、未確定点のIDだけを別出力で提案する。原本も既存の監視も変更しない。これは従来の追跡方式の入力選択を修正したもので、新しい人物検出モデルや追跡精度の保証ではない。

2026-11-07の比較スナップショット `results/tracking_v2/identity_short_anchor_v2_benchmark_20261107_01/` では、計画上の単独歩行を除く189録画のうち、旧方式で候補なしだった６録画に候補が現れた。従来一組だった候補に変更や消失はなかった。候補数は正答数ではない。グループ２録画005の132観測は過去の15 m版候補と時刻・位置・IDが一致したが、全区間の正解を確認したことにはならない。

既存の共有画像が利用できたグループ２録画005・018、グループ４録画030について、10時刻を抽出して候補点を同時刻の画像に投影した。離れた時刻の点は対象人物付近に見えたが、人物が重なる遠方の時刻には判別が難しいものがある。全フレームの正解注釈や３次元の位置精度の検証ではない。映像照合ページは `results/tracking_v2/identity_short_anchor_v2_pilot_review_20261107_01/index.html`、照合フレーム・入力ハッシュは同じフォルダーの `review_manifest.json`。

現行候補一覧は `results/tracking_v2/identity_short_anchor_v2_live_20261107_01/index.html`。同名の `.log` および一覧内 `summary.json` に更新・失敗が記録される。既存候補と内容が完全一致するものはハッシュを照合して再利用する。新着の反映には `python3 -m corridor_tracking.short_anchor_identity_v2 --watch` を利用できる。グループ６以降の録画番号・実施条件や人物数が未確認の場合、その条件を正解とみなさない。動画はSSDに残し、追加で共有しない。
