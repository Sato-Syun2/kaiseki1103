# 実験条件を使ったID候補の確認

指定された `experiment_recorder/inputs/追い越し実験_完成版_18グループ.xlsx` のSHA-256が、既存の `experiment_metadata/run_order_20261103.json` に記録された計画原本と一致することを確認した。照合に使う計画は録画進捗と対応付ける。計画は実際にその条件で歩行したことの証拠ではない。グループ６、グループ７追加試行、グループ９試行９等は既存の例外ルールにより条件を保留する。

`corridor_tracking.overtaking_condition_review` は、元の10 m版を変えず、既存の未検証ID候補のうち、２人の同時観測から前後関係が逆転したものを探す。両者が同方向へ歩き、並走付近で左右の差が持続する場合に限り、計画された追い越し方向と比較する。左右は歩行者の進行方向に対する左右であり、単純な画像左右ではない。廊下座標系の基底の向きと進行方向から変換する。観測点は深度から得た可視表面であり身体中心ではない。条件不明、同時観測不足、順序が逆転しない場合などは保留する。

閾値は開発用であり実測検証済みではない。同時位置20点以上・１秒以上、先頭と末尾の各窓３点以上、両者のX移動0.5 m以上、前後の差が開始・終了時とも0.15 m以上で逆転、並走の判定は前後差0.45 m以内の５点以上かつ0.15秒以上、その区間の横差中央値0.20 m以上かつ75%以上で横差の符号が一致、という条件を使う。異なる時刻の両者を組み合わせず、欠測点の補間もしない。誤検出や暫定IDの入れ替わり、実際の行動が計画と異なった場合でも、見かけ上の一致・不一致が起こる。

`results/tracking_v2/overtaking_condition_review_20261108_02/` は400録画のスナップショット。追い越し方向の比較ができた126録画のうち123件が計画と同じ側、３件が逆側に見えた。これは候補の正解率や不正解率ではない。逆側の録画はグループ２ `recording_017`、グループ４ `recording_022`、グループ７ `recording_007`。前２件の並走付近は既存共有画像を１時刻ずつ確認し、比較に用いた２点がそれぞれ別の人物の付近にあることを確認したが、全経路のIDや実際の指示は未検証。グループ７の映像はSSDで確認する。

既存方式が複数候補として保留したグループ４の録画013・037について、`results/tracking_v2/overtaking_ambiguous_review_20261108_01/` に各候補を別々に再生できるようにした。録画037では一候補が計画方向と一致するが、もう一候補は観測不足で比較できないため、どちらも自動採用しない。位置・時刻と元IDは変更せず、未割当て点への仮IDのみ別出力に作る。

いずれも自動更新されないスナップショット。追加分を評価するときは別の未使用出力先を指定する。

```sh
python3 -m corridor_tracking.overtaking_condition_review --output results/tracking_v2/overtaking_condition_review_NEW
python3 -m corridor_tracking.overtaking_ambiguous_review results/tracking_v2/overtaking_ambiguous_review_NEW
```

元データ・現行の候補・実行中のWindows SDKを変更しない。IDの正解や精度向上を確かめるには、方向一致・不一致・観測不足から独立して選んだ録画について、元画像で２人を継続的に注釈した比較が必要。
