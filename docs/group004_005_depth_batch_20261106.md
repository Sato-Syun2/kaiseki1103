# グループ４・５の深度解析

グループ４の37録画とグループ５の録画進捗で完了した54録画を対象とする。グループ４・録画006は試験済みの結果を照合し、残り90録画を解析する。人物位置は骨格を使わず、画像の人物領域と深度から可視表面の代表点を求める。IDは暫定。

グループ４のBODY出力から録画時刻とカメラ情報だけを利用する。グループ５は `export_svo_timeline.py` でSVOのフレーム時刻とカメラ情報をローカルに取得し、骨格処理は行わない。深度区間とは別SDKパスで取得し、全フレーム・時刻・SVOハッシュ・カメラを照合する。グループ５のSVO時刻取得はSDK模擬試験済みで、Windows実機での確認は未実施。

カメラ設置位置が４・５・６で同じという現場情報に基づき、グループ４の校正録画から作った床・壁の暫定変換を４・５に適用する。測量基準による独立検証はない。各録画のカメラ番号、解像度、設置ID、単位、座標系、内部パラメータを照合し、内部パラメータの差が１画素以下の場合のみ録画に対応した暫定校正を作る。深度点の復元には各録画の内部パラメータを使う。１画素の制限は適用範囲を絞るための判定であり、位置誤差の検証値ではない。

Windows SSDで処理し、共有先には `positions.json` と `manifest.json` だけを送る。確認用画像・再生ページはSSDに残し、画像と深度の重複した中間データは完了・検証後に整理する。再解析時は元SVOが必要。途中停止時は既存結果を消さず、再開時に完了済み結果を照合し、未完了の出力とは別のrun IDを選ぶ。共有済みなのに再生や整理が未完了の場合は自動的に再処理せず停止して確認する。

SDK・座標変換の模擬試験と追跡関連テストは30件通過。録画006の試験結果は352フレーム・ハッシュを照合済みで、利用者が再生を確認。一括プログラム、グループ５の時刻取得および内部パラメータ差の扱いはWindows実機で未検証。校正・追跡の独立した精度検証は未完了。
