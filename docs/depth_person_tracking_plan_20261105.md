# 骨格に依存しない歩行位置推定：計画

## 目的と方針

人物の歩行位置とIDを、SDKの骨格関節・骨格ID・骨格位置を入力せずに推定する。左画像の人物領域とZED深度を主な入力とし、位置とIDが決まった後にだけ、対応する骨格を表示用に重ねる。SDKは深度の取得には使うため、SDKそのものから独立する計画ではない。元データと既存の骨格由来の再生は維持し、新方式は別の出力として比較する。

SDK側の実装・実行は [`tracking_v2/AGENTS.md`](../zed_sdk_package/tracking_v2/AGENTS.md) に従う。深度書き出しの正本は同ディレクトリに置き、廊下座標変換・追跡・再生はUbuntu側で行う。SDK 5.5以降に付属する `pyzed` と動作済み環境を使用し、深度モードは `NEURAL` とする。SVOは読み取り専用で扱い、入力・設定・フレーム時刻と取得失敗を記録する。Windowsでローカルに新規出力を作ってから共有先に同期し、既存の配布物や結果は上書きしない。Ubuntuでの確認とWindows SDK実機での検証は区別する。

最初に求めるのは**人物として分離された可視表面の代表点**である。これは骨盤・身体中心・足の接地点の実測値ではない。校正後に床面へ投影した点も、歩行者中心の正解とは扱わない。身体中心や足元が必要なら、別に定義と測量基準を設けて誤差を検証する。

## 現在使えるデータと制約

- グループ3録画018には、既存BODY出力に加えて、同一SVO・時刻を照合済みの左画像と深度が17フレーム分ある。フレーム3〜9は連続し、以降は間引かれている。深度は別SDKパスでNEURAL、2画素おきに保存された有効な3D点であり、人物マスクや信頼度画像は保存していない。
- 固定した服付近の画像領域では、フレーム3〜9の深度中央値は手前約9.18〜9.20m、奥約12.87〜12.90mだった。矩形は人物の正解領域ではなく、背景の混入もあり得る。別パスの深度がBODY内部で使われた値と一致する保証はない。[確認結果](../results/tracking_v2/group003_018_depth_replay_diagnosis_20261105.md)
- 録画018には暫定の廊下座標変換があるが、測量による独立検証は終わっていない。[校正手順](tracking_calibration_capture.md)
- 17フレームの点群ファイルは圧縮約74 MiBで、展開した点とフレーム番号は約107 MiB。既存の深度書き出しは点群をメモリに蓄積してから保存するため、長時間の全フレームを同じ設定で一括出力する前に、メモリと容量を実測する。必要なら分割保存または逐次処理を実装する。
- このUbuntu環境には人物検出に使えるライブラリが存在するが、2026-11-05時点ではNVIDIAドライバーに接続できない。モデルの重みや実際の推論動作・処理速度は未確認。CPUでの小規模検証を先に行い、全フレームのGPU処理は利用可能なSDK PC等で確認する。SDK環境の依存関係を無条件に変更しない。

## 処理の構成

1. **人物領域の検出**：左画像から、SDK骨格を使わない人物検出・インスタンス分割を行う。最初の候補はYOLO系の人物分割とし、モデル・重み・バージョン・入力サイズ・閾値・ライセンスを記録する。枠だけの人物検出も比較候補とする。小さな遠方人物や前後の重なりで、両者を分離できるか画像で確認する。モデルの一般ベンチマーク値を今回の精度とみなさない。[Ultralyticsの人物を含むインスタンス分割](https://docs.ultralytics.com/tasks/segment)
2. **深度点の選択**：検出マスクと同一画像座標に対応する深度点を取り、無効値と明らかな背景混入を除く。マスク端の除外、深度方向のまとまり、連続成分、床・背景の除外を比較する。小さい人物では端を削りすぎると点がなくなるため、条件を距離と可視状態ごとに検証する。単に枠内の中央値だけを取り、奥の人物を背景として捨てない。
3. **代表点の算出**：選ばれた点の座標ごとの中央値など、外れ値に強い方法を候補とし、選んだ点数・深度分布・画像上の領域を併記する。可視部分の変化や身体の向きで表面代表点は動く。これを補正で身体中心と呼ばず、サンプル不足・複数人物混入・深度分布の分離失敗は位置未確定とする。しきい値は調整データだけで決めて固定し、未見データで評価する。
4. **追跡**：各時刻の検出を、画像位置・外観・深度代表点・経過時間による動きで一対一に対応付ける。追跡IDは新たな録画内IDとする。重なりで人物対応が一意でない場合は保留し、他人の点を強制的に結合しない。短時間の予測を表示する場合も、深度に支持された観測と別区分にする。完全に隠れた人物は観測済みとしない。
5. **座標変換と保存**：深度点のカメラ座標から廊下座標への変換は、同じ設置ID・カメラ情報に対応する暫定校正を用いる。カメラ座標も必ず残す。画像のフレーム番号・ns時刻、マスクまたは参照先、検出スコア、使用点数、表面代表点、校正版、ID、品質理由、観測／予測の区別を保存する。SDKの画像と深度は左画像に対応して取得でき、必要なら信頼度画像も取得できる。[ZED深度API](https://docs.stereolabs.com/docs/development/zed-sdk/modules/depth-sensing/using-the-api)
6. **表示専用の骨格対応**：位置・IDの確定後、同時刻の画像上で人物領域と骨格候補を一対一に照合する。2人にまたがる骨格や対応が曖昧なものは表示保留。対応できた骨格は、表示用の基準点が表面代表点に重なるよう平行移動できるが、これは身体中心を測ったことを意味しない。原骨格と移動後を切り替え、移動量・位置との対応根拠を表示する。関節配置の異常や混合は平行移動では直らない。位置・ID推定へのフィードバックは禁止する。

画像と深度はSVOハッシュ、カメラ設定、フレーム番号と画像時刻で照合し、不一致は拒否する。カメラ座標はIMAGE系の右・下・前、深度はカメラ前方Zであり、廊下X軸や斜距離と混同しない。人物領域の描画・座標変換・点群選択は、同じ左画像のピクセル座標を使う。

## 段階と成果物

### 1. 既存17フレームで成立性を確認

- 録画018の既存の左画像・2画素間隔の深度点を使用。対応フレームと入力ハッシュを確認する。画像から人物の可視領域を手動注釈し、人物が曖昧・完全遮蔽の場合も記録する。フレーム3〜9は連続例、残りは疎な例として区別する。
- まず手動領域と深度で代表点を試す。次に外部の自動検出・分割を加える。手動領域でうまく分離できない場合は深度側の問題、自動領域だけで悪化する場合は検出側の問題として切り分ける。枠＋深度とマスク＋深度も同じ画像で比較する。
- 画像上に検出領域・使った深度点・除外点・代表点・人手ラベルを重ね、深度の分布、点数、人物ごとの未確定理由を出す。既存SDK骨格も参考表示するが、人物検出や位置計算には渡さない。入力から骨格情報を除外した検査も行う。
- 完了条件：手前・奥の可視人物を分離できた時刻、失敗時刻と原因を画像ごとに報告する。7連続フレームは追跡の簡易確認に限り、17点から録画全体の精度やID維持率は結論しない。

### 2. 連続区間で軌跡を比較

- 録画018の冒頭を含む連続区間の左画像・深度を追加出力し、同じSVOのBODYと突合する。まず短区間を出力して実際の容量・時間を測る。左画像と深度を同じフレームで保存し、SDKの深度信頼度画像が使える場合は設定・範囲を明記して併せて保存する。現状の書き出しコードは信頼度画像と長時間の分割出力には未対応のため、必要な変更とWindows実機での検証が先に必要。
- 既に確認した録画018を開発例とする。別に未確認の録画から、単独歩行、離れた2人、前後に重なる2人、追い越し、画面端・遠方を含む連続区間を、結果を見る前に選ぶ。必要な深度がなければ同条件で追加出力する。録画番号、範囲、選定理由と調整／評価の区分を先に固定する。
- 画像を見ながら可視人物の領域と録画内IDを時系列に注釈し、完全遮蔽・判別不能を区別する。追い越し前後と遮蔽区間は連続フレームで確認する。疎な注釈だけの区間はその間のIDの正解が不明であると示す。
- SDK骨盤由来の既存位置と、画像・深度由来の新位置を、同じ画像時刻・同じ可視人物・同じ評価対象で比較する。表面代表点と骨盤は別の点なので、両者の座標差をそのまま位置誤差と呼ばない。検出漏れ・対応不能を分母から黙って除外せず、両者で比較可能な点数と全可視人物時刻の取得状況の両方を出す。
- 指標は、可視人物の検出・支持位置の取得割合、誤検出、ID取り違え・誤統合・分断、最大欠測、追い越し前の取得状況、急な飛びの候補、処理時間・容量。飛びの少なさだけで採用せず、見失いと誤って保留した例を併記する。画像と軌跡を同期した比較再生、観測の出所・不確定理由、入力とモデルのハッシュを出力する。

### 3. 位置精度と再生の妥当性を独立検証

- 絶対精度が必要な場合、設置ごとに既知位置の標的で校正し、異なる位置・撮影の検証用標的で誤差と欠測を測る。人物の歩行位置自体については、身体中心や足元など**何を正解とするか**を先に定義し、測量済みの床上位置と独立に同定できる基準を用意する。可視表面の代表点の評価とは別にする。
- 単独歩行と重なり、距離帯、画面端を分け、符号付き偏り・距離誤差・欠測を報告する。正解のない既存映像では、安定性や画像整合性の評価にとどめる。
- 骨格の原表示・位置合わせ後・骨格非表示を比較し、混合骨格を誤って対応させた件数と表示保留を画像で確認する。位置合わせ後の骨格を動作解析の真値と扱わない。

## 採用判断

調整例で方式と閾値を固定してから未見区間を評価する。新方式を候補とするには、可視人物の取得、誤対応、ID分断、位置の飛び、処理時間を併記し、既存方式に対する改善と悪化の両方を説明できることが必要。取得点数が少ないことで飛びが減った場合は改善と判定しない。絶対誤差や取得率の採用閾値は、必要な用途・許容誤差を決めるまで未確定とし、検証後に結果を見て都合よく設定しない。十分な独立検証ができない間は実験用の別出力にとどめる。

最初の実装対象は段階1とする。新たな検出結果や深度点に対する再生・追跡コードは、既存の骨格ベース出力を上書きせず、実行ごとに新しい出力ディレクトリへ保存する。
